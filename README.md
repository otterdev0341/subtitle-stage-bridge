# Botnoi Live Relay

ต้องการสร้าง boradcast service โดย ส่ง link ไปยัง คอมอีก 2 เครื่อง ซึ่งเปิดแล้วจะแชร์จอ กลับมา,
โดยเครื่องแรก จะแชร์ เป็น presentation ใน canvase ซึ่งจะเปิดเต็มจอ มีการปรับ ขยับ, เครื่องที่สองจะเป็น translation จะเป็นจอดำ ๆ แล้วมีข้อความ, โดยแพลตฟอร์มจะต้องสามารถ ครอป ลาก ได้ เพราะต้องการจะพรีเซ็นในรูปแบบ subtitle มา overlay บน ที่เปิด presentaiton

This project was built with [Lovable](https://lovable.dev).

## Control Room · Preview / Program และซับ Gemini

แผนและเกณฑ์ตรวจรับอยู่ใน [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)

- **Live**: เปรียบเทียบ Preview กับ Program; กด **TAKE** หรือ Space เพื่อส่งฉากที่เตรียมขึ้น LIVE ส่วนปุ่มพักจอ/จอดำ/ซ่อนภาพในแถบ LIVE ทำงานทันที ไม่ต้อง TAKE
- **Sources**: แท็บ A–E แสดงภาพที่ส่งมาหลัง crop และแยกสถานะเชื่อมต่อ/กำลังเลือก/เปิดบน Program มีลิงก์เครื่องส่งและปุ่มแสดง/ซ่อนแต่ละจอ การเลือกแท็บไม่เปลี่ยน LIVE
- **Scene Editor**: แก้ Mask, Content, z-order, visibility, opacity, templates และพักจอใน Preview ใช้ TAKE เมื่อพร้อม การซูมพื้นที่ทำงานไม่เปลี่ยนภาพข้างใน
- **Translation**: พิมพ์ข้อความแล้วแปลด้วย Gemini หรือรับเสียงไมโครโฟน/มิกเซอร์/แท็บเป็นช่วงสั้น เลือก Review เพื่อตรวจแล้วส่ง หรือ Auto เพื่อส่งเมื่อแปลเสร็จ ภาพ B และซับข้อความแสดงพร้อมกันได้
- **ค้างซับ** หยุดการแทนที่อัตโนมัติและพักเวลาหมดอายุ; **ซ่อนซับ** เปลี่ยนการมองเห็น; **ล้างซับ** ลบข้อความ; **หยุดรับเสียง** ยกเลิกผลแปลที่ยังรออยู่ ทุกคำสั่งแยกกัน
- **Presenter Link** รับเฉพาะ Program และซับ ไม่มีเครื่องมือแก้ไข กด F เพื่อเต็มจอ ปุ่มเปิดเต็มจอจะหายไป; **จอฉายพร้อมปุ่มลัด** ส่งคำสั่งกลับ Control Room และรอการยืนยัน เปิดแผงด้วย `?`
- Program ล่าสุดเก็บใน sessionStorage ของแท็บควบคุมเพื่อกู้คืนเมื่อ refresh; templates/glossary เก็บใน localStorage ประวัติคำแปล 50 รายการอยู่ในหน่วยความจำ ไม่บันทึกวิดีโอหรือเสียงในแอป

### ตั้งค่า AI บนเซิร์ฟเวอร์

ใช้ `LOVABLE_API_KEY` ที่ Lovable จัดการใน Secrets เท่านั้น ไม่ใช้ `VITE_` ไม่ส่ง key ไป browser และไม่ใส่ค่า secret ใน Git ตั้ง `GEMINI_TRANSLATION_MODEL` ฝั่งเซิร์ฟเวอร์ได้ (ค่าเริ่มต้น `google/gemini-3.8-flash`); ตรวจสิทธิ์โมเดล/เครดิตที่ workspace ใช้งานจริง

การแปลเรียก `https://ai.gateway.lovable.dev/v1/chat/completions` ผ่าน TanStack server function ทั้งข้อความและ WAV mono สั้น ๆ ใช้ gateway Gemini chat model ไม่ใช่ Gemini Live WebSocket API เสียงแบ่งเมื่อหยุดพูดหรือยาวครบ 8 วินาที จึงต้องทดสอบจุดตัดคำ ความหน่วง ชื่อเฉพาะ ตัวเลข และคุณภาพไทย/อังกฤษกับเสียงงานจริงก่อนใช้หน้างาน ไม่มีการเปิดฟังอัตโนมัติหรือส่งภาพหน้าจอให้ AI

มีขีดจำกัด 20 คำขอต่อนาทีต่อห้องและ 600 คำขอต่อชั่วโมงต่อ server instance เพื่อจำกัดการใช้งานเบื้องต้น (in-memory จึงรีเซ็ตเมื่อ deploy และไม่ใช่ billing cap ข้ามหลาย instance) หน้า Translation จำกัด 300 คำขอต่อรอบเปิดหน้า ไม่มี automatic paid retry หาก AI ไม่พร้อมยังพิมพ์และส่งซับเองได้ ต้องทดสอบ gateway audio acceptance ด้วย Secrets ที่ตั้งแล้ว

ปุ่มเพิ่มเติม: `C/D/E` แสดงหรือซ่อนแหล่งภาพ C/D/E, `S` แสดง/ซ่อนซับ; shortcuts ไม่ทำงานขณะพิมพ์ เลือกแท็บ หรือปรับค่าในฟอร์ม ต้องเปิด Control Room ไว้สำหรับ TAKE และคำสั่ง LIVE ที่ sync ทุกจอ เครือข่ายที่บล็อก P2P ยังต้องทดสอบการเชื่อมต่อจริงตามข้อจำกัด WebRTC เดิม

รายละเอียดด้านล่างอธิบาย geometry เดิมซึ่งยังใช้ใน **Preview**; การแก้ scene จะมีผลต่อ Program หลัง TAKE

## การส่งภาพและควบคุมเวที

- เครื่อง A/B: กดเลือกจอ แล้วลากกรอบบน preview (หรือเลือกแถบคำบรรยาย) ตรวจภาพตัวอย่างก่อนกด **เริ่มส่งภาพเฉพาะส่วนนี้** ระบบส่ง canvas ที่ตัดภาพแล้วเท่านั้น
- ระหว่างส่ง: **ปรับพื้นที่ส่ง** เปิดกรอบฉบับร่าง ภาพเดิมยังส่งต่อจนกด **ใช้พื้นที่นี้**; **ยกเลิก** คงกรอบเดิมไว้
- หน้าควบคุม: เลือก A/B แล้วใช้ **ปรับ Mask** เปิด/ปิดพื้นที่ภาพ, **ปรับ Content** เลื่อน/ขยายภาพต้นทาง หรือ **ย้ายทั้งเลเยอร์** ย้ายสองกรอบพร้อมกัน
- **ซูมพื้นที่ทำงาน** มีผลเฉพาะหน้าแก้ไข: Fit ให้พอดีพื้นที่, 100% แสดงขนาดพิกเซลเวทีจริง; ใช้แถบเลื่อนเพื่อดูส่วนอื่นเมื่อซูม
- ล็อกเลเยอร์เพื่อป้องกันการลาก, ล็อกสัดส่วน Mask เมื่อต้องการ; Content คงสัดส่วนภาพเสมอ, ใช้ Undo/Redo ย้อนการจัดภาพได้โดยไม่ยกเลิกพักจอหรือจอดำ
- ในแท็บ **เทมเพลต** เลือก Layout สำหรับช่องลัดปุ่ม 4–8 ได้ รวมถึงเทมเพลตที่บันทึกเอง ช่องลัดถูกส่งไปยังจอฉายพร้อม layout

ปุ่มลัดใช้ได้ทั้งหน้าควบคุมและหน้าจอฉาย:

| ปุ่ม                            | คำสั่ง                                     |
| ----------------------------- | ---------------------------------------- |
| 0                             | กลับ LIVE และยกเลิกจอดำ                    |
| 1 / 2 / 3                     | พักทั้งเวที: รอสักครู่ / ชื่อเรื่อง / ขัดข้องทางเทคนิค |
| 4–8                           | Layout ช่องลัด 1–5 (เปลี่ยนได้ระหว่างพักจอ)     |
| H / P                         | แสดงหรือซ่อน B / A                         |
| K                             | สลับจอดำ                                  |
| F / Esc                       | เปิดหรือปิดเต็มจอ / ออกจากเต็มจอ              |
| ?                             | เปิดหรือปิดแผงปุ่มลัด                          |
| Ctrl/Cmd+Z / Ctrl/Cmd+Shift+Z | Undo / Redo ในหน้าจัดเวที                   |

ต้องเปิดหน้าควบคุมไว้เพื่อรับคำสั่งจากจอฉายและกระจายสถานะเดียวกันทุกจอ หากไม่มีการตอบรับ จอฉายจะแจ้งข้อผิดพลาดแทนการเปลี่ยนเฉพาะจอนั้น แถบปุ่มและ cursor ซ่อนเมื่อเต็มจอและไม่มีการขยับเมาส์; เปิดแผงด้วย `?` ได้ตลอด ปุ่มลัดไม่ทำงานขณะพิมพ์หรือปรับ slider

ตรวจการเปลี่ยนแปลงในเครื่องด้วย `npm test`, `npx tsc --noEmit` และ `npm run build` จากนั้นทดสอบ A/B กับจอฉายบนอุปกรณ์จริงก่อนใช้หน้างาน

### Content และ Mask แบบแยกอิสระ

กรอบสีเขียวคือ Mask และกรอบสีน้ำเงินคือ Content การลด Mask ไม่เปลี่ยนขนาด/ตำแหน่งของ Content หรือตัวหนังสือ ส่วนการขยาย Content คงสัดส่วนภาพและไม่ขยาย Mask ตาม เลือกโหมดย้ายทั้งเลเยอร์เพื่อย้ายทั้งคู่โดยคงองค์ประกอบภายในไว้

- ช่องตัวเลขอ้างอิงพิกเซลของเวที แยกจากซูมพื้นที่ทำงาน Content สามารถยื่นออกนอกเวทีได้; Mask จำกัดอยู่ในเวทีหรือพื้นที่แบ่งจอ
- Scale ของ Content อ้างอิงความกว้างภาพต้นทางที่ได้รับ (100% = ขนาดพิกเซลภาพต้นทาง) ความกว้างและความสูง Content เปลี่ยนแบบคงสัดส่วนเสมอ
- **Fit Content**, **Fill Mask**, **Center Content** เป็นคำสั่งครั้งเดียว การปรับ Mask หลังจากกดไม่เรียก Fit/Fill ซ้ำ
- เส้นประและภาพจางนอก Mask ช่วยจัดภาพในหน้าแก้ไข จอฉายแสดงเฉพาะภาพภายใน Mask
- Layout/ช่องลัด/เทมเพลตและ Undo/Redo เก็บทั้ง Mask และ Content โดยใช้สถานะร่วมกันทุกจอ การปรับสัดส่วนแบ่งจอเปลี่ยน Mask เท่านั้น
- Layout เดิมยังเปิดได้ ระบบใช้ขนาดภาพจริงเพื่อแปลง Fit/Fill/zoom เดิมเป็นตำแหน่ง Content ครั้งเดียว หาก Layout มี crop เดิม จะมีปุ่ม **คืนภาพเต็มที่ A/B ส่งมา** โดยรักษาสเกลภาพที่เห็นอยู่
- เมื่อภาพจาก A/B เปลี่ยนความละเอียด ระบบคงความกว้าง Content และปรับความสูงให้ตรงสัดส่วนภาพใหม่; ไม่เปลี่ยน Mask
